# v14：同一 Wi-Fi／局域网与连接重试

基于已发布的 v12 通用版。包名 `com.shihab.diplay.ora81`，versionCode **43**，
versionName `0.2.10-android81-test14-lan-universal`。使用原签名，可覆盖旧版并保留设置。
应用名保持 **Diplay**；CarPlay 返回入口使用 DiPlay 图标和“返回车机”。
支持 Android 8.1 及以上，APK 同时包含 ARMv7、ARM64、x86、x86_64。

## 同一 Wi-Fi／局域网

1. 在系统设置中，让车机和 iPhone 连接同一路由器、随身 Wi-Fi 或另一台手机的热点。
2. 打开 DiPlay → 设置 → 连接设置，选择“同一 Wi-Fi／局域网”。
3. 输入这个外部网络的准确名称及密码，然后保存。SSID 两端的空格也会保留。
4. 保持车机与 iPhone 蓝牙配对、蓝牙开启，再开始连接。

推荐 WPA2-Personal 或 WPA2/WPA3 混合模式；开放网络才可以留空密码。
路由器必须允许设备相互通信和 mDNS，关闭客户端隔离。优先使用两台设备均支持的 5 GHz。
DiPlay 使用已有 Wi-Fi 连接，不自动切换 Wi-Fi、不创建热点。外部网络详情与车机热点详情分别保存。
不要求局域网本身能上网；在线地图和音乐仍需可用的互联网连接。
WPA3-only、企业认证及网页认证网络不在本次支持范围内。

## 启动与重试

- 车机热点最多等待 120 秒，兼顾好猫开机后热点启动较慢的情况；关闭连接可以取消等待。
- 连续 3 次确认同一热点地址后才发布服务，发布服务及向 iPhone 发出启动指令前再次核对地址。
- 启动指令发送后 30 秒没有实际 CarPlay TCP 接入，会清理该次连接并重试。
- 热点或局域网未就绪、上述 TCP 超时按 2、4、8、16、30 秒延迟最多重试 5 次。
- 可检测的名称、安全类型等配置不匹配时停止自动重试；检查配置后点“重新连接”。
- 已有画面但手机没有打开可选 iAP2 隧道时保留画面，释放蓝牙引导连接。
- 地址变化会重新建立连接；旧连接的清理及回调受到代次检查保护。
- 稳定播放 60 秒后重置本次启动重试预算。普通已建立会话断线沿用原恢复策略。

## 来源与验证

选择性移植原作者上游提交 `31b8dfc` 至 `1b35633`（Same LAN）、`118ad7b`（启动恢复），
并包含 `c4c6024` 的无需 Android NSD 服务发现修复，以及 `a81e05b` 所解决的旧交接超时覆盖错误保护。
热点等待实现保留本分支原有 120 秒策略，并补充稳定性检测；没有引入上游比亚迪 ADB 热点控制功能。
保留本分支已有哈曼蓝牙交接、媒体与导航音频焦点、Siri 导航音道及方向盘切歌处理。

发布附件中的 `VALIDATION-v14.zip` 记录实际构建、测试、ABI、签名、覆盖安装和界面检查结果。
本次 v14 尚未在 ARM 实机或车机与 iPhone 的真实连接中验证，因此以预发布提供。
上游的其他车辆验证和此前好猫版本的用户反馈不等同于本次 v14 实车验证。
